# 第四章6.22
以下是根据代码提交历史（2025年5月1日至5月8日）整理的开发章节脉络与核心内容概要：

---

### 第一阶段：底层数据序列化与基础算法扩展 (5月1日 - 5月2日)
**核心内容：基础优化与背包空间判断**
* **序列化与函数优化**：实现了 `Fast Array Serializer`（快速数组序列化器）和 `Fast Array Functions`，为背包数据在网络同步或存档时提供高效的底层支持。
* **空间检查机制**：加入了背包是否满载的检查逻辑（`Has Room for Item` 与 `No Room in Inventory`），这是物品能否成功拾取或放入的前提基础。

### 第二阶段：物品属性、网络同步与事件机制 (5月6日)
**核心内容：完善物品元数据及 RPC 核心通信**
* **物品数据定义**：引入了 `Item Manifest`（物品清单/清单配置）和 `Item Type Tags`（物品类型标签），用于区分和分类不同的物品属性。
* **网络网络同步 (RPCs)**：添加了 `Add Item RPCs`，确保在多端/网络环境下，物品的添加操作能够正确同步。
* **事件触发**：实现 `On Item Added` 逻辑，当物品成功加入背包时，触发相应的回调或UI更新事件。

### 第三阶段：UI拆分、片段化管理与网格校验 (5月7日)
**核心内容：UI 架构优化与片段化解耦**
* **槽位物品基础**：定义了 `Slotted Item`（已入槽物品）的基本概念与逻辑。
* **网格合法性检查**：实现了 `Inventory Grid Check`，用于实时校验物品在网格背包中的放置位置是否合法、是否重叠。
* **Fragment（片段）化UI设计**：将 UI 拆分为 `Image Fragment` 和 `Item Fragment`。通过片段化设计，提升了 UI 组件的复用性，使物品图标、文本及数量等展现形式更加灵活。

### 第四阶段：网格槽位动态更新与画布交互 (5月8日)
**核心内容：完整的网格渲染与物品交互闭环**
* **画布交互**：实现 `Add Slotted Item to Canvas`，将物品真正渲染并添加到 UI 画布上。
* **纹理与视觉表现**：引入 `Grid Slot Textures`，为背包的每一个网格槽位赋予视觉纹理。
* **高级循环与数量控制**：
    * 通过 `For Each 2D` 循环来遍历二维网格槽位。
    * 实现 `Stackable Fragment` 与 `Stack Count`，支持物品的堆叠功能及堆叠数量的数字显示。
* **状态实时同步**：实现 `Updating Grid Slots`，确保当物品发生拖拽、使用或丢弃时，网格槽位的状态和表现能够动态更新。

---
总结：本系统从底层的快速数组与网络同步开始，逐步构建物品清单，随后深入到二维网格的碰撞校验，最终完美实现了支持堆叠、动态更新且表现层解耦（Fragment化）的现代网格背包系统。

# 第九章7.16-7.24

继续完成背包物品的点击放置、交换和堆叠处理：

5. 新增 SwapWithHoverItem：拖动物品与另一个物品发生冲突并点击时，将鼠标物品放入候选位置，同时把被点击物品拿到鼠标上。

# 第十章7.25

开始实现背包物品的右键弹窗和堆叠拆分：
1. 新增 ItemPopUp 弹窗控件，包含拆分、丢弃、使用按钮，以及选择拆分数量的滑块和数量文本；按钮通过动态委托把操作类型、格子下标和拆分数量传回 BagGrid。
2. 右键点击 SlottedItem 时由 BagGrid 创建弹窗，将 GridIndex 记录到弹窗实例，并把弹窗放到鼠标位置；子背包蓝图需要把 ItemPopUpClass 配置为 WBP_Inv_ItemPopUp。
3. BagGrid 只保存一个 ItemPopUp：已有有效弹窗时不重复创建；弹窗离开鼠标区域或执行已绑定按钮后会移除，OnItemPopUpDestruct 只在销毁对象确实是当前弹窗时清空指针。
4. 创建弹窗时根据物品能力决定可用操作：只有可堆叠且数量大于 1 的物品显示拆分区域；数量为 1 或不可堆叠时隐藏拆分按钮、滑块和数量文本；不可使用的物品隐藏使用按钮。
5. 拆分滑块最多只能选择原数量减 1，默认选择约一半；滑块值转成整数后至少为 1，只有一个可选数量时锁住滑块，避免显示或提交拆分数量 0。
6. 点击拆分后，BagGrid 根据弹窗保存的 GridIndex 找到物品左上角格子，将原堆叠数量减去拆分数量并同步 SlottedItem 显示，再创建携带拆出数量的 HoverItem 让玩家继续放置。
7. 目前已完成右键弹窗的创建、关闭、操作显隐和堆叠拆分；Drop 与 Consume 已完成按钮及委托连接，但 OnPopUpMenuDrop 和 OnPopUpMenuConsume 仍为空，实际丢弃和使用逻辑尚未实现。

# 第十一章7.26

完成背包物品的丢弃逻辑：
1. 点击弹窗的 Drop 后，BagGrid 先通过 PickUpBagItem 把整堆物品转成 HoverItem 并清空原格子，再由 DropItem 把 BagItem 和丢弃数量发送给服务器，最后清理鼠标上的 HoverItem。
2. Server_DropItem 根据 TotalStackCount 扣除丢弃数量；剩余数量为 0 时从 BagList 删除该物品，否则更新剩余总数，然后调用 SpawnDroppedItem 生成地面掉落物。
3. SpawnDroppedItem 在玩家前方随机计算生成位置，把丢弃数量写入 ItemManifest 的 StackableFragment，再由 SpawnPickupActor 创建对应 Actor，并把清单复制到该 Actor 的 ItemComponent 中，这样拾取就包含数量
4. 目前已完成整堆物品的丢弃、地面 Actor 生成及清单同步；OnPopUpMenuConsume 仍为空。当前 SpawnDroppedItem 通过引用直接修改 BagItem 的 Manifest，能够传递掉落数量，但也会改变原清单。
